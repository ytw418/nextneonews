# 언니노트 앱 결정 (2026-10-21)

초안·투자자 2명·타깃 가상 인물 4명·반박 검증을 거친 분석과, 그 뒤 사용자가 내린 결정을 함께 적는다. 외부 출처는 2026-10-21 에 열었다. ESTIMATE 는 추정, 미확인은 확인하지 못한 것이다. 코드는 커밋 `96f0f12` 기준으로 읽기만 했고 개발 서버는 띄우지 않았다.

## 사용자 결정 (2026-10-21)

- **웹뷰 기반 앱을 먼저 만든다. 서비스 구조와 수익 구조가 잡히면 사용성 좋은 네이티브로 다시 만든다.** 아래 분석은 "지금은 웹, 기준을 넘으면 앱"을 권했지만, 사용자가 순서를 정했다.
- 그래서 1판은 §5 의 (3) 하이브리드다. 화면 대부분은 웹뷰이고, 하단 탭·저장함·알림만 네이티브로 둔다. 얇은 웹뷰 래퍼(2)는 Apple 4.2 반려 위험 때문에 하지 않는다. 웹이 콘텐츠의 원본이라 구조를 바꿔도 앱 업데이트 없이 반영된다. 구조가 아직 바뀌는 지금 단계와 맞는다.
- §4 의 숫자 기준은 "앱을 시작할지" 대신 "네이티브로 다시 만들지"와 "앱에 얼마나 더 투자할지"를 정하는 데 쓴다. 측정(설치 카드 이벤트·이메일 칸, §6)은 그대로 한다. 앱이 나오면 이메일 대기 명단에 출시 알림을 보낸다.
- 광고: iOS 앱 1판은 애드센스를 끈다. Android 는 Google Mobile Ads SDK 웹뷰 등록(WebView API for Ads)을 갖춘 뒤에 켠다(§1 '웹뷰 안 광고').

## 0. 분석 결론 (사용자 결정 전)

- **지금은 앱을 만들지 않는다. PRD §12 "네이티브 앱 (PWA 로 충분)" 은 "지금은 웹, 기준을 넘으면 하이브리드 앱" 으로 고쳐 쓴다.**
- 이유는 세 가지다. ① 앱을 쓸 사람이 있는지 아직 재지 못했다(없다고 확인된 것이 아니다). ② 외부 방문이 월 약 1,500~3,200(ESTIMATE, 일 50~107명 × 30) 이라 앱을 내도 월 설치는 수 명~수십 명이다. ③ iOS 4.2 반려와 웹뷰 광고 정책 위험은 실재하고, 받을 것이 작을 때 질 위험이 아니다.
- 브리디 앱 출시로 바뀐 것은 **비용**이다(EAS·스토어 자동화·계정). 수요 쪽은 바뀌지 않았다. 비용이 싸졌으니 수요가 보이면 3~5주 안에 따라잡을 수 있고, 그래서 미리 만들 이유가 더 없다.
- 오늘은 **수요를 재는 장치와 소유 채널(이메일)** 을 웹에 넣는다. 설치 카드 이벤트, 저장 직후 설치 카드, 이메일 한 칸("앱 출시 알림 + 주간 소식"). 약 1.2 작업일(ESTIMATE). 푸시 서버와 저장함 서버 백업은 이 숫자가 나온 뒤 조건부로 한다(§7).
- 사용자가 "그래도 지금" 을 고른다면 (2) 얇은 웹뷰가 아니라 (3) 하이브리드로, iOS 부터, §5 설계대로 만든다. 기대치는 실험 수준(월 설치 약 11명, ESTIMATE)이다.

## 2. 검증에서 받아들인 것과 받아들이지 않은 것

**받아들여 고친 것**
- 초안의 핵심 근거 "설치 탭 0 → 앱 설치는 더 낮다" 를 지웠다(반박 F2, 투자자 B, 타깃 검증 모두 같은 지적. 코드로 확인했다).
- `login.md` 표기를 ①안 → **B안** 으로(①은 PRD §12 번호, `docs/predeploy/login.md:69`). AdMob 연쇄를 "계정 폐쇄 시" 로. Expo 58 = RN 0.88 확정. "설치 없이 iOS 푸시" → "홈 화면 추가 없이". 기회비용은 "수집·작성·번역은 `.github/workflows/pipeline.yml` 2시간 cron 이 계속 돈다. 멈추는 것은 운영자가 직접 하는 가이드·개선이다" 로.
- 산식: 90일 목표 1,000명을 앱 설치로 채우려면 설치율 1%·3개월 누적 가정에서 월 모바일 방문 약 3.3만, 0.2% 면 약 16.7만. 지금 모바일 월 약 1,000~2,150(ESTIMATE) 의 15~160배. 초안의 "6.7만~33만, 20~100배" 는 가정(1.5개월)이 숨어 있고 분모가 전체 방문이라 바꿨다(투자자 A).
- 착수 기준에서 "7일 재방문 15%" 와 "설치 클릭 2%" 를 뺐다. 전자는 앱·푸시가 만들 결과를 조건으로 건 순환 논리(반박 ②-2), 후자는 카드만 고쳐도 넘는 느슨한 기준이고 앱 수요가 아니라 PWA 카드를 잰다(타깃 검증 2). 대신 소유 채널 동의 수와 iOS 대기 명단을 주 기준으로 올렸다(투자자 A·B, 반박 ④-2).
- 오늘 작업에서 푸시 서버·`PushDevice`·저장함 서버 백업·앱 모드 UA 꼬리표를 뺐다(투자자 A·B). 앱에 "수요 0" 기준을 대면서 같은 기준을 웹 선투자에 대지 않는다는 지적이 맞다. 이메일 한 칸을 먼저 넣는다(투자자 A·B, 반박 ③ "가짜 문"). 설치 카드를 저장 직후에 띄우는 변경은 넣는다(타깃 검증 1, 4명 모두 "저장 직후" 를 꼽음. `SUMMARY.md` 추천 3번과 같은 방향).
- 90일 목표 "설치·푸시 구독 1,000명" 은 어느 길로도 불가능하다(반박 ③). PRD 에 재정의를 제안한다(§7).
- 알림 소재 1순위를 투표 마감 → 팔로우한 팀의 컴백 D-1 로(타깃 검증 3). 푸시를 만들 때 `entityIds` 구독 설계는 유지한다.
- iOS Chrome 홈 화면 안내(반박 ③), 개발자 페이지 묶임 위험(반박 ③), 저장함 서버 백업은 기기 바꿈을 못 푼다는 점(타깃 검증 4)을 문서에 넣었다.

**받아들이지 않은 것**
- "지금 iOS 하이브리드를 내야 한다"(반박 ②): 가장 강한 반대안이지만 절대 규모가 막는다. iOS 외부 방문 월 약 1,300(ESTIMATE, 3,200 × 41%), 2% 설치해도 월 26명. MAMA(11/20~21) 전 출시는 제작 3~5주 + 심사로 가능성이 낮다. 스토어 검색·미디어킷 자산은 맞는 말이지만 수십 명 규모에서는 효과가 없다.
- 투자자 B 의 "저장함 백업은 외부 저장 사용자 월 100명 전까지 보류": 조건부 보류는 받아들이되 문턱은 낮춘다. 백업은 앱 설치자만이 아니라 웹 방문자 전체에 효과가 있고 비용이 1~2일이라, 외부 저장 사용자 월 30명이면 한다(ESTIMATE, §7).
- 투자자 A·B 의 "재방문 신호를 기기에 `hb:first-seen` 으로 저장": 넣지 않는다. iOS 7일 삭제로 iOS 만 적게 잡히고(반박 ③), EEA ePrivacy 해석이 미확인이다. 사람 수·재방문은 GA4(동의 모드 적용 중, `HeadScripts.tsx`) 사용자 수로, 저장 목록 복귀는 이미 있는 `saved_view.oldestDays`(`SavedView.tsx:77-80`)로 본다.
- 계정 연쇄 위험 기대값(투자자 A): 금액으로 쓰지 못한다. 애드센스 수익은 검토 중이라 0, 브리디 AdMob 수익은 미확인이다. 구조만 적는다. 상방은 월 설치 수십 명, 하방은 두 계정 폐쇄(확률 낮음, 등록을 제대로 하면 더 낮음, ESTIMATE). 지금은 지지 않는다.

- **PRD 90일 목표 재정의**: "홈 화면 설치·푸시 구독 1,000명" → "재방문 채널 동의(이메일·웹푸시·설치) 300명"(ESTIMATE. 모바일 월 약 2,150 에서 이메일 2%·Android 푸시 10% 가정 시 3개월 300~400명).
- **Android TWA**: 외부 Android 비중이 40% 를 넘고 Play 계정 테스트 요건을 확인하면 검토.

## 10. 1단계 구현 (2026-10-21)

사용자 결정(웹뷰 먼저)에 따라 하이브리드 앱 1단계를 만들었다. 저장소 루트 `mobile/` (Expo SDK 58·RN 0.88·expo-router NativeTabs·react-native-webview 14). 루트 `workspaces` 밖이라 웹 배포·Actions `npm ci` 와 무관하다.

**구성**
- 하단 탭 5개(홈·랭킹·가이드·일정·저장)는 네이티브. 앞의 넷은 탭마다 웹뷰 하나(처음 고를 때 만들고 유지), 저장은 네이티브 목록(`GET /api/saved` 로 제목·커버) → 항목은 같은 탭 안 웹뷰로 연다.
- 앱 식별: 웹뷰 UA 끝 `UnnieNoteApp/<버전>` → 웹이 `html[data-app]` 을 켜고(서버 분기 없음, 앱·사파리 서버 HTML 이 같다) 웹 탭바·설치 카드·언어 제안·이메일 칸·댓글·RSS 를 숨기고 광고 요청을 멈춘다(`apps/web/src/lib/app-mode.ts`).
- 저장 원본은 앱(AsyncStorage). 페이지마다 그리기 전 `localStorage['hb:saved']` 를 심고, 웹에서 저장·해제하면 메시지로 받아 다른 탭 웹뷰에도 다시 심는다(`mobile/src/lib/bridge.ts`, `store/saved.ts`). 사파리 7일 삭제와 무관하다.
- 링크: 다섯 탭 첫 화면 → 네이티브 탭, 사이트 밖(제휴 포함) → 앱 안 사파리 창, mailto·일정 .ics·RSS → 시스템. 오프라인 화면·다시 시도, 웹 언어를 바꾸면 앱 언어(탭 이름)도 따라간다.
- 아이콘은 사이트 로고와 같은 Instrument Serif 이탤릭 'U.'(`mobile/scripts/make-icons.mjs`). 탭·저장함 문구는 웹 메시지에서 뽑는다(`mobile/scripts/gen-strings.mjs`).

**돌려 보기**

- 앱: `cd mobile && LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 EXPO_PUBLIC_APP_ENV=development EXPO_PUBLIC_SITE_URL=http://localhost:3420 npx expo run:ios --configuration Release --device "iPhone 16 Pro"`. CocoaPods 는 UTF-8 로캘이 없으면 죽는다. Release 는 JS 를 넣어 Metro·개발 런처 없이 뜬다.
